## 一、游戏概述

### 1.1 一句话定位

《Subnet：暗流》是一款 7 人策略博弈桌面游戏。玩家扮演去中心化 AI 子网中的不同角色——子网所有者、验证者、矿工——通过数据提交、审计核查、筹码交易、合约投票等行动积累个人筹码，最终按筹码占比瓜分奖励池。**没有团队胜利，只有个人结算排名**。

### 1.2 游戏参数

| 项目 | 数值 |
|------|------|
| 人数 | 7 人（1 子网所有者 + 3 验证者 + 4 矿工，其中 1 矿工为初始隐藏叛徒） |
| 时长 | 约 60-90 分钟，共 3 轮 |
| 初始筹码 | 每人 15 筹码 |
| 公共池初始 | 14 筹码（每人上缴 2 筹码） |
| 外部奖励池 | 120 筹码（固定） |
| 子网所有者协议费 | 外部奖励池的 30%（36 筹码），无论合约是否达成都全额获取 |
| 玩家分红 | 外部奖励池的 70%（84 筹码）+ 公共池剩余，按个人筹码占比分配 |

### 1.3 游戏背景

游戏模拟一个去中心化 AI 子网的博弈生态：子网所有者制定底层经济规则，矿工提供数据服务，验证者负责核查矿工服务质量并排名。玩家经历三轮策略博弈，最终通过全体投票判定链上合约是否生效，按筹码持有量结算奖励。

### 1.4 数字化实现对应

本规则描述的是**桌面游戏**（由 DM 主持）的玩法。当转化为数字 DEMO 时，DM 的职责由服务端 GameEngine 替代。可参考配套的《5 小时极简 DEMO 开发文档》。

## 二、角色定义

### 2.1 角色总览

| 角色 | 人数 | 初始筹码 | 核心能力 |
|------|------|----------|----------|
| **子网所有者** | 1 | 15 | 设置分配权重；发起审计（1 筹码/次）；调用大模型分析；终局踢出玩家；投票权重 0.5（公开大模型报告后升为 1.0） |
| **验证者** | 3 | 15 | 对矿工评分（1-100）；匿名举报矿工虚报（免费）；与任意玩家匿名交易筹码 |
| **矿工** | 4 | 15 | 提交 1-5 星质量声明（可诚实、可虚报）。其中 1 人为**初始隐藏叛徒**，拥有收编/反叛特殊机制 |

### 2.2 子网所有者详细能力

| 能力 | 说明 | 成本 |
|------|------|------|
| 设定分配权重 | 每轮开始前可微调矿工与验证者的奖励分配比例（默认矿工 70% / 验证者 30%），以及矿工排名内部分配比例 | 无 |
| 设定公共目标 | 全局目标，如"三轮累计矿工真实贡献≥60 星"（仅供参考，当前版本未强制关联结算） | 无 |
| 强制审计 | 选择一个矿工，揭示其真实质量，触发奖惩 | 1 筹码/次 |
| 大模型分析 | 调用三个等级的数据分析服务，获得可疑度报告（可选择公开或保密） | 低端 1 / 中端 3 / 高端 6 筹码 |
| 终局踢出 | 终局阶段强制审计全部矿工后，踢出已证实的虚报矿工（也可自主踢出其他可疑玩家） | 无 |
| 发起合谋质疑 | 对决中疑似合谋包庇的验证者发起质疑，由剩余存活矿工投票判定 | 2 筹码/次 |

### 2.3 验证者详细能力

| 能力 | 说明 | 成本 |
|------|------|------|
| 评分排名 | 独立对 4 名矿工打 1-100 分，用于计算矿工排名 | 无 |
| 匿名举报 | 在审计阶段开始前，匿名举报任意矿工虚报 | 无 |
| 匿名交易 | 与任意玩家私下协商筹码转账（见 6.2 节） | 交易金额 + 约定条件 |

### 2.4 矿工详细能力

| 能力 | 说明 |
|------|------|
| 质量声明 | 秘密填写 1-5 星服务质量声明，提交给子网所有者（DM）。可诚实填报，也可虚报博取更高排名 |
| 叛徒收编 | 仅叛徒矿工可用。向普通矿工支付贿赂筹码，将其收编为同伙（见 6.1 节） |
| 脱离叛徒 | 被收编的矿工可支付赎金脱离叛徒控制（贿赂金额 × 2） |

### 2.5 角色限制

- 一个地址（玩家）只能扮演一个角色
- 被踢出的玩家永久丧失投票权和最终奖励分配资格
- 叛徒身份在游戏开始时由 DM 秘密分配，仅叛徒本人知晓

## 四、核心机制速览

### 4.1 矿工虚报与罚款

```
矿工提交声明质量（1-5 星）
          │
          ▼
    ┌─ 声明 ≤ 真实 ──→ 诚实（无后果）
    │
    └─ 声明 > 真实 ──→ 虚报
          │
          ▼
    若被审计证实虚报：
    罚没 5 筹码 → 审计者得 4 筹码 → 公共池 +1 筹码
```

### 4.2 验证者举报

```
验证者在审计阶段开始前匿名举报某矿工虚报
          │
          ▼
    该矿工在本轮被审计证实虚报 → 举报有效 → 举报者得 4 筹码（从罚款中抵扣）
    该矿工未被审计或审计证实诚实 → 举报无效 → 无后果
```

**注意**：举报是零成本的，但不能撤回。滥用举报虽无直接惩罚，但可能暴露验证者自身的策略倾向。

### 4.3 审计费用与收益

| 操作 | 成本 | 收益（若证实虚报） | 若无虚报 |
|------|------|-------------------|----------|
| 审计 1 名矿工 | 1 筹码（归公共池） | 得 4 筹码 | 仅扣除审计费 |
| 终局全员审计 | 免费 | 按虚报数量获得罚没收益 | 无 |

### 4.4 每轮代币分配

```
每轮从公共池抽取 8 筹码
          │
    ┌─────┴─────┐
    ▼           ▼
矿工群体 70%  验证者群体 30%
（5.6 筹码）  （2.4 筹码）
    │
    ▼
矿工按排名分配：第 1 名 40% / 第 2 名 30% / 第 3 名 20% / 第 4 名 10%
```

**注意**：三轮共支出 24 筹码，公共池初始仅 14 筹码，存在透支可能。若分配时公共池余额不足，按实际余额等比缩减本轮分配量。（虚报罚款每笔补充 1 筹码入公共池。）

### 4.5 合谋惩罚

```
子网所有者支付 2 筹码发起质疑
          │
          ▼
    剩余存活矿工投票判定
          │
    ┌─────┴─────┐
    ▼           ▼
  证实合谋     未证实
    │           │
    ▼           ▼
验证者罚 5 筹码  质疑方损失 2 筹码
所有者得 3      无其他惩罚
公共池 +2
```

### 4.6 合约投票

- 投票资格：所有未被踢出的存活玩家
- 投票权重：子网所有者默认 0.5（公开过大模型报告则为 1.0）；其余玩家权重均为 1
- 通过条件：**赞成票数 ＞ 总有效票数的 2/3**（等于不算通过，必须超额）

## 五、完整游戏流程

### 阶段 0：初始设置（约 5 分钟）

1. DM 随机分配角色。每位玩家获得 15 初始筹码。
2. 所有玩家向公共池上缴 2 筹码 → 公共池初始 = 14 筹码。
3. 子网所有者设定：
   - 每轮分配权重（默认矿工 70% / 验证者 30%）
   - 矿工排名内部分配比例（默认 40%/30%/20%/10%）
   - 全局公共目标（如"三轮累计真实贡献≥60 星"）
4. DM 秘密生成每名矿工的本轮真实质量（1-5，随机），选定叛徒身份，全程保密。

### 三轮常规流程（每轮约 15-20 分钟）

**第 1 步：矿工提交质量声明（3 分钟）**

- 所有矿工秘密填写 1-5 星质量声明，提交给 DM。
- DM 将声明与之前生成的真实质量配对记录，全程保密。

**第 2 步：验证者评估排名 + 匿名操作（3 分钟）**

- 三名验证者独立对四名矿工打分（1-100 分），提交排名给 DM。
- 验证者同时可选操作：
  - 免费匿名举报任意矿工虚报（在审计阶段开始前提交）
  - 与任意玩家私下协商匿名筹码交易（见 6.2 节）

**第 3 步：子网所有者强制审计（可选，3 分钟）**

- 子网所有者可自主选择审计对象，每审计 1 名矿工需支付 1 筹码（归入公共池）。
- 审计后 DM 揭示该矿工的真实质量，触发奖惩：
  - 证实虚报：矿工罚没 5 筹码 → 审计者（所有者）得 4 筹码 → 公共池 +1 筹码
  - 证实诚实：无奖惩，仅扣除审计费
- 此阶段验证者的举报被核实 → 若被举报矿工被审计证实虚报，举报有效，举报者得 4 筹码。

**第 4 步：轮次代币分配（2 分钟）**

- DM 对三名验证者的排名结果取平均值，生成矿工最终排名。
- 从公共池取出 8 筹码：
  - 矿工群体得 70%（按排名比例分配）
  - 验证者群体得 30%（按子网所有者预设权重分配）

**第 5 步：全局匿名交易阶段（5 分钟）**

- 所有玩家可自由私下协商，完成匿名筹码转账交易。
- 交易可附加个性化条件（如"放弃举报""后续投票支持"等）。
- 所有条件仅为口头约定，无系统强制约束力（桌面玩法的特点）。

**第 6 步：大模型数据分析（可选，3 分钟，仅子网所有者）**

子网所有者可选择消费筹码调用分析服务，获得秘密报告。报告可选择公开或保密：

| 等级 | 成本 | 输出内容 |
|------|------|----------|
| 低端 | 1 筹码 | 历史数据偏差最大的 2 名可疑矿工 |
| 中端 | 3 筹码 | 2 名高概率虚报矿工 + 可疑度评分 + **附带低端分析内容** |
| 高端 | 6 筹码 | 最高概率虚报矿工 + 最高概率收受贿赂的验证者 + 精准置信度 |

**公开报告的额外效果**：子网所有者的终局投票权重从 0.5 永久提升至 1.0；但如果公开的报告内容被后续事实证伪（如指认的矿工实为诚实），权重回落至 0.3。

**加密报告的原始数据可随时上链存证，对局结束后由 DM 揭示加密密钥。**

**第 7 步：轮次结算记录**

DM 统一记录：所有玩家筹码变动、累计真实贡献星数（计入公共目标进度）、本轮事件日志。进入下一轮。

### 三轮结束：最终结算（约 10 分钟）

**步骤 A：全员矿工强制审计**

子网所有者免费审计全部 4 名矿工，统一核查虚报行为，锁定最终违规名单。

**步骤 B：违规玩家踢出**

子网所有者踢出经审计证实的虚报矿工，也可自主选择踢出其他可疑玩家。被踢出玩家永久丧失投票权与最终奖励分配资格。

**步骤 C：验证者最终报告 + 合谋核查**

- 三名验证者独立提交「应踢出矿工名单」
- 子网所有者可消耗 2 筹码，对决中疑似包庇虚报矿工的验证者发起合谋质疑
- 剩余存活矿工投票判定 → 证实合谋：验证者罚没 5 筹码（所有者得 3，公共池 +2）

**步骤 D：链上合约投票**

- 所有存活玩家投票（赞成/反对）
- 通过阈值：赞成票数 ＞ 总有效票数 × 2/3

**步骤 E：最终奖励分配**

**情况 1：合约成功达成**
1. 子网所有者固定获取外部奖励池 30%（36 筹码）
2. 剩余 70%（84 筹码）+ 公共池剩余筹码 → 按存活玩家的个人筹码占比分配

**情况 2：合约未达成**
1. 子网所有者仍全额获取 36 筹码协议费
2. 外部奖励池剩余 70%：50% 永久燃烧，50% 均分给所有存活玩家
3. 公共池剩余：50% 燃烧，50% 均分给所有存活玩家

## 六、特殊机制详解

### 6.1 叛徒与收编机制（显式状态机）

叛徒矿工拥有"收编"其他普通矿工的能力。为确保规则清晰可执行，叛徒相关的矿工状态按以下状态机流转：

```
                    ┌── 被叛徒支付贿赂收编 ──→ Compromised（被控制）
                    │                              │
   Normal（正常）  ──┤                              ├── 支付赎金（= 贿赂金额 × 2）──→ Normal
                    │                              │
                    │                              └── 主动反叛揭露 ──→ Exposed（揭露）
                    │                                                       │
                    └── 自身即为叛徒 ──→ Traitor（叛徒）                     ▼
                                              │                  罚没 6 筹码，退出游戏
                                              │
                                              ├── 支付贿赂 ──→ 收编目标矿工 → Compromised
                                              └── 被反叛揭露 ──→ Exposed（同上）
```

**规则说明**：

- **收编**：叛徒在任意匿名交易阶段向目标普通矿工支付贿赂筹码（金额由叛徒决定），目标可选择接受或拒绝。接受后目标变为 Compromised 状态。
- **Compromised 矿工的行为**：被收编后，该矿工仍独立操作，但叛徒可私下向其下达指令（如"虚报 5 星""给某验证者低分"等）。是否执行指令由被收编者自主决定，但不执行可能面临叛徒的报复。
- **脱离**：Compromised 矿工可在任意匿名交易阶段支付**贿赂金额 × 2** 的赎金给叛徒，恢复为 Normal 状态。
- **反叛揭露**：Compromised 矿工可在任意时刻公开揭露叛徒身份，自身变为 Exposed 状态 → 罚没 6 筹码（归公共池），退出游戏。叛徒的身份随之暴露，其他玩家可据此调整策略。

### 6.2 匿名交易机制

**桌面游戏规则**：
- 玩家在匿名交易阶段私下协商筹码转账金额和附加条件
- 所有条件为口头约定，无系统强制约束力
- 适用于桌面环境下的玩家间信任博弈

**数字化实现建议**：
- 分为两种模式：
  - **口头交易**：保留现有规则，低成本但高风险
  - **托管交易**：双方将筹码锁入系统托管，条件达成自动结算。收取 5% 手续费归公共池
- DEMO v0.1 暂不实现交易系统

### 6.3 随机数生成

桌面游戏中由 DM 掷骰子并公开记录，即可满足透明性要求。

数字化实现中建议采用 **commit-reveal** 方案——服务端在游戏开始时提交随机种子哈希，游戏结束后公开种子，玩家可验证所有随机结果。正式版由 TEE Enclave 的 Beacon 服务生成可验证随机数。

## 八、游戏测试指南

### 8.1 测试核心目标

1. **规则完整性**：排查流程漏洞、逻辑矛盾、规则歧义
2. **数值平衡**：排查角色强弱失衡、固定必胜策略、数值崩坏
3. **策略多样性**：验证是否存在多种有效博弈打法

### 8.2 各环节测试重点

| 环节 | 核心测试问题 |
|------|-------------|
| 矿工声明 | 5 筹码罚款是否过高，导致矿工完全放弃虚报策略？虚报风险收益比（约 1:2.5）是否合理？ |
| 验证者评估 | 4 筹码举报奖励是否充足？验证者合谋机制是否容易成型？零成本举报是否被滥用？ |
| 所有者审计 | 1 筹码审计费是否合理？多轮多对象审计是否撑得住？ |
| 代币分配 | 7:3 角色分配比例是否公平？公共池透支如何处理？ |
| 匿名交易 | 口头约定模式是否导致争议？是否需要托管交易？ |
| 大模型分析 | 三档性价比是否合理？高端分析是否因成本过高被闲置？ |
| 终局投票 | 2/3 阈值在不同留存人数下难度是否均衡？ |

### 8.3 数值调整建议

| 当前值 | 测试后可能调整方向 |
|--------|-------------------|
| 虚报罚款 5 筹码 | 若矿工普遍放弃虚报 → 降至 3-4 筹码；或引入"首犯警告" |
| 举报奖励 4 筹码 | 若举报被滥用 → 引入"诬告惩罚"（举报失败扣 1 筹码） |
| 单轮分配 8 筹码 | 若三轮必透支 → 降至 5-6 筹码，或改为随公共池浮动 |
| 高端分析 6 筹码 | 若使用率过低 → 降至 4 筹码，或增加"附带历史趋势图" |

### 8.4 测试方法

1. **纸上推演**：用表格模拟完整单轮对局，记录所有决策分支与筹码变动
2. **小规模试玩**：1-2 轮试玩，收集直观反馈
3. **核心清单核查**：角色失衡 / 规则歧义 / 固定必胜策略 / 策略单一
4. **数值调优**：微调罚款、审计费、分配比例等参数，反复测试

## 九、附录：玩家快速参考卡

### 9.1 每轮行动顺序

```
1. 矿工秘密提交质量声明 (3 min)
2. 验证者打分排名 + 匿名举报 + 初步匿名交易 (3 min)
3. 子网所有者选择性审计 (3 min)
4. 公共池发放 8 筹码额外奖励 (2 min)
5. 全局自由匿名交易 (5 min)
6. 子网所有者可选大模型分析 (3 min)
7. 轮次结算，进入下一轮
```

### 9.2 终局专属流程

```
A. 全员矿工强制审计（免费）
B. 违规玩家踢出（虚报矿工 + 可疑玩家）
C. 验证者提交最终报告 → 合谋质疑核查
D. 合约投票（赞成 > 2/3）
E. 最终奖励分配
```

### 9.3 核心规则速记

1. 子网所有者投票权重：默认 0.5 → 公开报告后 1.0 → 报告证伪后 0.3
2. 虚报罚款：5 筹码（审计者 +4，公共池 +1）
3. 验证者合谋罚没：5 筹码 / 人（所有者 +3，公共池 +2）
4. 合约达成条件：赞成票 ＞ 总票数的 2/3
5. 3 轮不变：每轮声明 → 评分 → 审计 → 分配 → 交易 → 分析循环

### 9.4 信息保密原则

- 你 **不知道** 他人的真实质量，除非审计揭示
- 你 **不知道** 他人的筹码数（除非对方主动告知）
- 你 **不知道** 他人是否在举报你
- 你 **不知道** 验证者给其他人打了多少分
- **你能相信的只有 DM 的公开揭示，和你的博弈直觉**
